# Архитектура

## Два независимых процесса

Сборщик открывает страницу в видимом Chromium с отдельным постоянным профилем. Пользователь работает в собственной авторизованной сессии. Обработчик ответов сохраняет только JSON, в котором найден ожидаемый список заявок. Монитор читает готовые файлы, сравнивает идентификаторы и обращается к Telegram Bot API.

Процессы связаны каталогом снимков, а не общим Python-объектом. В текущем прототипе предусмотрен один экземпляр монитора и один браузерный профиль.

| Модуль | Ответственность |
| --- | --- |
| `config.py` | Настройки из окружения и `.env`, валидация интервалов, настройка логирования |
| `browser/downloader.py` | Сессия Playwright, обновление страницы и отбор JSON-ответов |
| `parsing.py` | Поиск списков `boSearchBoardItems.items` и нормализация ID |
| `monitor.py` | Разность множеств, обработка файлов и повторные попытки |
| `notifications/messages.py` | Текст уведомления и группы ограниченной длины |
| `notifications/telegram.py` | Получатель и HTTP-запросы `getUpdates` / `sendMessage` |
| `storage/files.py` | Чтение JSON и атомарная запись снимков и состояния |

## Контракт снимка

Минимальный поддерживаемый фрагмент выглядит так; идентификаторы в примере вымышлены:

```json
{
  "data": {
    "boSearchBoardItems": {
      "items": [
        {"id": "demo-order-001"},
        {"id": "demo-order-002"}
      ]
    }
  }
}
```

Этот объект может находиться внутри другой структуры или массива ответов. Парсер объединяет ID из всех найденных списков. Произвольные поля `id` вне нужного пути не используются. Строковые и целочисленные ID приводятся к непустой строке; `null`, `bool` и сложные объекты пропускаются. Пустой список является допустимым снимком.

Это контракт, выделенный из исходного проекта, а не обещание неизменности внутреннего формата сайта. Маршрут `/graphql` сам по себе недостаточен: дополнительно проверяются content type и структура данных.

## Состояние и подтверждение доставки

В `state.json` хранится объект с массивом `known_ids`. Файл отсутствует — известных ID пока нет. Повреждённый JSON или неверный формат вызывают ошибку, а не незаметный сброс истории.

Для каждого снимка монитор вычисляет `new_ids = snapshot_ids - known_ids`. При отсутствии новых ID отправка не производится. Остальные ID сортируются и разбиваются на сообщения с консервативным ограничением 4000 UTF-16 единиц.

Для каждой группы порядок такой:

1. Отправить уведомление и получить успешный ответ Telegram.
2. Записать объединённый список известных ID в файл.
3. Обновить множество в памяти.

Если отправка не подтверждена, ID группы не записываются в состояние, а файл остаётся доступен для повторной обработки. Если предыдущие группы уже подтверждены и сохранены, они не отправляются заново при обычном повторе. Если запись состояния завершилась ошибкой после доставки, возможен дубль.

Атомарная запись создаёт временный файл в том же каталоге, закрывает его и заменяет целевой. Монитор не читает промежуточный `.tmp` как снимок. Это защита от частично записанного JSON, но не транзакция между Telegram и диском.

## Повторные попытки

Каталог проверяется каждые `POLL_SECONDS`. Обработанный файл идентифицируется именем, временем изменения и размером. При ошибке чтения, обработки или доставки повтор разрешается после `RETRY_SECONDS`.

Список обработанных файлов хранится только в памяти. После перезапуска снимки читаются снова, а сохранённые `known_ids` предотвращают обычную повторную отправку. Неуспешный старый файл не блокирует чтение остальных; строгого порядка доставки между файлами пока нет.

## Получатель и конфигурация

Предсказуемый адресат задаётся через `TELEGRAM_CHAT_ID`. Если значение пустое, адаптер выбирает чат из последнего подходящего сообщения в доступном `getUpdates` и кэширует его до остановки процесса. Этот режим предназначен для личного бота; он не реализует выбор пользователей или подписки. Входящие сообщения из другого чата могут повлиять на автоматический выбор.

Настройки по умолчанию:

| Переменная | Значение | Назначение |
| --- | --- | --- |
| `SITE_URL` | `https://profi.ru/backoffice/n.php` | Открываемая страница |
| `MATCH_URL` | `/graphql` | Фрагмент URL ответа |
| `MIN_REFRESH_SECONDS` / `MAX_REFRESH_SECONDS` | `10` / `50` | Диапазон паузы перед обновлением |
| `POLL_SECONDS` | `1` | Пауза между проверками каталога |
| `RETRY_SECONDS` | `30` | Пауза после неуспешной обработки |
| `TELEGRAM_TIMEOUT_SECONDS` | `10` | Таймаут HTTP-запроса |
| `DOWNLOADS_DIR` | `runtime/downloads` | JSON-снимки |
| `BROWSER_PROFILE_DIR` | `runtime/browser-profile` | Локальная сессия Chromium |
| `STATE_FILE` | `runtime/state.json` | Известные ID |

Полный образец: [`.env.example`](../.env.example). Переменные уже заданного окружения имеют приоритет над `.env`. Значения токена и получателя исключены из строкового представления объекта настроек; сообщения HTTP-ошибок с URL бота не выводятся в журнал.

## Границы текущей версии

Проверки из [tests](../tests/README.md) не открывают реальный аккаунт и не отправляют сообщения. Нативный launcher macOS проверен на уровне shell-синтаксиса, но не выполнен в этой проверочной среде.

Пока нет долговечной очереди отправки, блокировки второго экземпляра монитора, очистки снимков или автоматического восстановления авторизации. Если Telegram принял сообщение, но ответ потерялся, последующая попытка может создать дубль. Проект не гарантирует полный охват всей ленты: он видит только списки, полученные открытой страницей.
